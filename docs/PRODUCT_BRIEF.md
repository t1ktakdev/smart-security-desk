# Product Brief

Заказчик: служба безопасности и IT-отдел колледжа/офиса.

Проблема: камеры, события датчиков и реакция оператора отслеживаются раздельно. Нужен единый локальный интерфейс.

Цель MVP: позволить просматривать состояние камер, фиксировать тестовые IoT-события и проводить инциденты от new до resolved.

Роли:
- Оператор: просмотр, создание и обработка инцидентов.
- Инженер: статус камеры, проверка доступности видеопотока.
- Администратор: локальный запуск и сопровождение (боевой RBAC не реализован).

Входит: камеры, online/offline, ссылка на MediaMTX, IoT events, incident status, assignee, status/severity filters, REST API, Dashboard и повторяемые тесты.

Не входит: распознавание лиц, NVR, production authentication, MQTT ingestion, push-оповещения.

Приёмка: npm start; 8 endpoints; 8 обязательных тест-кейсов; безопасные формы; тесты сохранения данных; GitHub Issues, PR и релиз или явная отметка о блокировке.

Риски: JSON-хранилище только для одного процесса и учебного сценария. Без защиты нельзя публиковать сервер для внешнего доступа.

Данные в базе и интерфейсе демонстрационные.
